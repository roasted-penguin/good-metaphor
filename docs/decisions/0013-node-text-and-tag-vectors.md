# 0013 노드 텍스트·태그 벡터 구성: 설정 두 개를 두고, 기본값(full/joined)은 그대로

- 상태: T-155에서 채택(조건). `tagVectorMode: "max"` + 감점 재조정을 `admin.json`에 넣음 (2026-11-09, T-155). T-154에서는 기각했었다. 노드 텍스트는 `full` 그대로
- 조건: 가드 회귀 2문장(API 분당 상한, 누진세)은 새 작업으로 따로 고친다(메인이 정함). 그때까지 `npm run eval -- --guard`는 이 2문장으로 실패한다

## 배경
T-153 분석(`docs/analysis/2026-11-09-holdout-gap.md`)에서 구조적 원인 하나를 찾았다. `nodeText`가 노드가 가진 태그의 설명과 **예문 전부**를 담는다(ADR 0009). 그래서 예문 한 줄을 바꾸면 그 태그를 가진 노드 여러 개가 함께 움직인다. 평가 문장에 맞춘 예문 조정(T-135)이 다른 문장에서 예측하기 어렵게 터지는 이유다. 분석은 두 가지 끊는 방법을 열린 선택지로 남겼다.

## 선택지
`admin.retrieval`에 설정 두 개를 두고 조합 네 개를 쟀다.

| 설정 | 값 | 뜻 |
| --- | --- | --- |
| `nodeTextMode` | `full`(기본) | 노드 텍스트 = 태그 `라벨: 설명` + 예문 + `이름. 사실`(지금과 같음) |
| | `desc` | 노드 텍스트 = 태그 `라벨: 설명` + `이름. 사실`. 예문은 빠진다 |
| `tagVectorMode` | `joined`(기본) | 태그 벡터 1개 = `라벨: 설명` + 예문을 한 텍스트로(지금과 같음) |
| | `max` | 태그마다 `tag:<id>`(설명만)와 예문마다 `tag:<id>#<n>`. 태그 유사도는 그중 최대값 |

구현:
- `lib/graph.js`의 `embedItems(graph, retrieval)`가 임베딩 항목(`{key, text}`)을 만든다. 확장 `ensureGraphVectors`와 `tools/eval.mjs`·`eval-gen.mjs`·`check-real-embed.mjs`·`smoke-providers.mjs`가 모두 이 함수에 `admin.retrieval`을 넘긴다. 그래서 평가와 실제 확장의 구성이 같다.
- `lib/retrieval.js`의 `tagSimilarity`는 `tag:<id>`와 `tag:<id>#1`, `#2`…(빈 번호에서 멈춤) 중 최대 코사인을 쓴다. `retrieve`와 `topTags`가 이 함수를 쓴다.
- 기본값이면 키·텍스트·점수가 이전과 바이트 단위로 같다(단위 테스트). 벡터 캐시 키(임베더 id + 텍스트 sha1)도 그대로다.
- 측정용으로 `npm run eval -- --retrieval '{"tagVectorMode":"max"}'`를 추가했다. 파일은 바꾸지 않고 `admin.retrieval` 위에 덮어쓴다.

## 측정 (실제 확장, e5-base q8, 한 문장씩, 2026-11-09)
`npm run eval -- --guard -v` / `--holdout -v`. 홀드아웃 A·B는 T-153과 같은 분할(seed 153)이다. 여유 수는 맞힌 문장 중 1위와 다음 노드의 점수 차가 0.005보다 작은 문장 수(평가셋·검증셋·홀드아웃 순)다.

| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| full/joined (지금) | 40/44 (43) | 12/12 | 9/9 | 6/6 | 13/14 | 14/20 (8·6) | 0 | 0 | 9·4·4 = 17 |
| desc/joined | 40/44 (42) | 11/12 | 9/9 | 6/6 | 12/14 | 13/20 (6·7) | **−2** | 1 | 6·2·3 = 11 |
| full/max | 41/44 (42) | 11/12 | 9/9 | 6/6 | 12/14 | **17/20 (8·9)** ※ | **+3** ※ | **4** | 6·5·5 = 16 |
| desc/max | 39/44 (43) | 10/12 | 9/9 | 6/6 | 11/14 | 13/20 (5·8) | −4 | 6 | 6·2·1 = 9 |

문장별 변화(지금 기준. 괄호는 여유 전 → 후):
- **desc/joined**: 회귀는 [가드] Leverage amplifies…(+0.0099 → −0.0079), 검증 운전면허 필기, 홀드아웃 A 은행 이체 한도·논문 투고. 새로 맞힌 문장은 Learning to code…, 홀드아웃 B airline fare sale.
- **full/max**: 회귀는 [가드] API 서버 분당 요청 상한(+0.0088 → −0.0087), [가드] 누진세(+0.0040 → −0.0053), [가드] 주식 신용거래(+0.0024 → −0.0026), [가드] 국채·장바구니 물가(+0.0052 → −0.0036), 홀드아웃 A 경품 응모권. 새로 맞힌 문장은 검을 대장간에 맡기면…, The gym lets each member…, Learning to code…, 검증 콘서트 티켓 되팔기, 홀드아웃 B 포토카드·airline·film set, 홀드아웃 A 수영 강습.
- **desc/max**: 가드 회귀 6개(full/max의 4개 + 주차장 요금, Players keep rerolling…)와 홀드아웃 회귀 5개. 새로 맞힌 문장은 7개.

※ T-155에서 다시 세어 보니 공식 출력의 홀드아웃 혼합 줄은 16/20(A 7·B 9)이었다. 홀드아웃 A 사과 상자 문장이 여유 +0.0000(동점)에서 1위를 놓쳤는데 비교표를 만들 때 여유 ≥ 0을 맞힘으로 셌다. 그래서 full/max(감점 그대로)의 실제 순이익은 **+2**다. 결론(기각)은 같다.

추상 태그 top-1은 max 모드에서 조금 오른다(평가셋 25 → 26, 검증셋 9 → 11, 홀드아웃 11 → 12).

### 벡터 수와 첫 로드 시간 (실제 확장 `embed:warmup`, 벡터 캐시를 비운 뒤, 모델은 이미 받은 상태, 2회)
| 조합 | 그래프 벡터 | 임베딩 시간 | 캐시가 있을 때 |
| --- | --- | --- | --- |
| full/joined | 36 | 24.8초 | 3ms |
| desc/joined | 36 | 15.3초 | 3ms |
| full/max | 94 (+58 예문) | 26.5초 | 3ms |
| desc/max | 94 | 16.8초 | 3ms |

예문은 짧아서 `max`가 벡터 수를 2.6배로 늘려도 시간은 약 7%만 는다. 시간은 긴 노드 텍스트(예문 포함)가 대부분 차지한다. 벡터 캐시 상한(T-110, 2,000개)에는 94개라 여유가 크다. 사용자 노드가 늘면 노드마다 1개, 사용자 태그 예문마다 1개씩 는다.

## 결정
**기각. 기본값 `full/joined`를 그대로 둔다.** 채택 기준은 세 세트 합계 순이익 +3 이상, 가드 회귀 2개 이하, 음성 6/6 유지, 여유 < 0.005 합계가 늘지 않음이다.
- desc/joined(−2)와 desc/max(−4)는 순이익에서 떨어진다. 노드 텍스트에서 예문을 빼면 금융·검증셋이 약해진다. 예문이 노드 직접 비교에서도 구조 신호로 쓰이고 있다는 뜻이다.
- full/max는 순이익 +3, 음성 6/6, 여유 16(≤ 17)으로 세 기준을 넘는다. 하지만 가드 회귀가 4개라 기준(2개 이하)을 넘는다. 회귀 4개 중 3개가 경제·금융 문장이고(누진세, 신용거래, 국채 물가), 검증셋 금융이 5/5에서 3/5로 떨어진다. 예문 하나가 질의와 가까우면 그 태그 전체가 이기기 때문에, 경제 예문을 가진 태그 쪽으로 다시 쏠린 것으로 보인다(`tagPenalty`는 `joined` 벡터 기준으로 정한 값이다).

`admin.json`은 바꾸지 않았다. 설정과 `--retrieval` 덮어쓰기는 남겨서 다음 시도(아래)를 다시 잴 수 있게 했다.

## 결과·남은 위험
- 코드 기본값과 `admin.json` 모두 지금과 같다. 검색 결과·벡터 캐시는 바뀌지 않는다.
- full/max는 홀드아웃에서 B 6 → 9로 가장 크게 올라, 일반화에는 도움이 되는 방향일 수 있다. 다만 B는 이제 이 측정에 한 번 쓰였다. 다음 시도의 확인용으로는 깨끗하지 않다.
- 다음에 해 볼 것(새 작업 후보, 메인이 정함): full/max에서 `tagPenalty`를 다시 맞추거나, 태그 유사도를 설명과 예문 최대값의 가중 평균으로 섞는 방식. 기준은 이번과 같다.
- 서버(LightRAG, ADR 0006)는 별도 경로라 이번 범위 밖이다. 서버의 엔티티 설명 구성은 바뀌지 않는다.
- 측정 원본: `.tmp/eval-154-<조합>-{guard,holdout}.txt`(로컬, 저장소에는 없음).

## T-155 재시도: max에 맞춘 감점 재조정 (채택)

### 먼저 새 홀드아웃
홀드아웃 B를 T-154에서 한 번 썼기 때문에 `tools/eval-unseen.json`에 새 12문장(`"batch": "T-155"`)을 먼저 더하고 커밋했다(금융 4, 영어 3, 기존 모든 세트·태그 예문과 3-gram < 0.5·< 0.3, 내용어 겹침 3개 미만). 조정 선택에는 쓰지 않았다. 화면 측정 도구는 이 12문장을 계산하지 않았고, 공식 eval은 선택이 끝날 때까지 기존 20문장 파일로 돌렸다. 채점은 마지막에 한 번만 했다.

### 방법
`nodeTextMode: full`, `tagVectorMode: max`로 두고 `tagPenalty`만 바꿨다. 예문·태그·노드·점수식은 그대로다. 감점은 질의 벡터·그래프 벡터를 바꾸지 않으므로 실제 확장에서 한 번 임베딩한 벡터로 후보를 화면 측정했다(스크래치 하네스, `embedItems` + `retrieve` 그대로). 태그 18개를 하나씩 0.01~0.08로 훑은 뒤(약 80개), 효과가 있던 `scarcity_value`·`market_price`·`inflation`·`temporary_multiplier`를 조합으로 훑었다(약 90개). 최종 값은 공식 `npm run eval`로 다시 쟀다.

한 태그만 바꿔서는 +3에 못 미쳤다. `scarcity_value` 0.02~0.03이 +3이지만 가드 회귀가 3이었다. `market_price` 감점을 0.02에서 낮추면(0~0.011) 검증셋 금융 2문장(신용거래, 국채 물가)이 돌아와 가드 회귀가 2가 된다. 다른 태그 감점(예: `loss_risk`, `cooldown`, `progression_gate`)은 모두 순이익이 줄었다.

### 바늘 끝 검사 (±0.002, 화면 측정)
채택 값 주변에서 결과가 바뀌는 경계:
- `inflation`: 0.022~0.034에서 같음(0.020과 0.036에서 순 +2·가드 회귀 3). 채택 0.03은 위쪽 경계에서 0.004.
- `market_price`: 0~0.011에서 같음(0.012에서 가드 "동네 아파트 매물"이 여유 −0.0003으로 틀려 가드 회귀 3). 채택 0.005는 양쪽에서 0.005 이상.
- `scarcity_value`: 0.018~0.038에서 같음(0.016에서 홀드아웃 A 1개 손실, 0.040에서 평가셋 1개 손실). 채택 0.03.
- 세 값을 함께 ±0.002 움직인 조합 10개도 모두 순 +3·가드 회귀 2·음성 6/6, 여유 합계 14~17(이전 17 이하).

### 결정
채택 기준(순 +3 이상, 가드 회귀 2개 이하, 음성 6/6, 여유 < 0.005 합계가 늘지 않음, 새 홀드아웃 12문장에서 나쁘지 않음)을 모두 넘는다. 모두 경계값 그대로(+3, 2개, 7 = 7)라서 여유 있게 넘은 것은 아니다. `admin.json`의 `retrieval`에 `tagVectorMode: "max"`와 감점 `{ inflation: 0.03, market_price: 0.005, scarcity_value: 0.03 }`을 넣었다.

### 남은 위험
- 가드 2문장(API 분당 상한 → 기간당 한도, 누진세 → 단계별 비용 증가)이 틀린다. 메인이 새 작업으로 고친다. 그때까지 `--guard`는 실패한다.
- 새 홀드아웃에서는 감점을 바꾸지 않은 full/max가 8/12로 채택 설정(7/12)보다 1개 많다. 차이는 희소성 문장 하나(은퇴 선수 공)이고, `scarcity_value` 감점이 그 문장을 직접 끌어내렸다. 표본이 하나라 결론은 못 내지만, 이 감점이 기존 세트에 맞춘 값일 수 있다는 신호다. 다음 홀드아웃 보충 때 희소성 문장을 더 넣어 확인한다.
- hit@3은 조금 내려갔다(평가셋 43 → 42, 기존 홀드아웃 17 → 16). 추상 태그 top-1(감점 없이 세는 값이라 max 벡터 자체의 효과)도 새 홀드아웃을 포함한 32문장에서 20 → 18이다.
- 그래프 벡터가 36 → 94개로 늘고 첫 임베딩이 약 7% 길어진다(위 표). 벡터 캐시 키는 임베더 id + 텍스트 sha1이라 노드 벡터 18개는 캐시를 그대로 쓰고, 태그 텍스트(설명만 18개 + 예문 58개)만 다음 실행 때 한 번 새로 임베딩한다.
- 측정 원본: `.tmp/eval-155-<cand|adopt|base>-{guard,holdout,holdout20}.txt`, 화면 측정 `.tmp/h155-*.txt`(로컬).

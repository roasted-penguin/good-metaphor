# 0010 말풍선 원클릭 피드백을 그래프에 반영한다

- 상태: 제안 (2026-10-18, 사용자 요청. 구현은 T-129 → T-106 → T-130·T-131·T-132, 동의 화면은 T-116, 저장·공유 범위는 D-7(결정))

## 배경
T-113에서 검색 가중치와 태그 예문을 손으로 조정했더니, 합계는 올랐지만 잘 맞던 문장이 새로 틀렸다. 30문장 평가셋과 작은 임베딩 모델로는 "어떤 문장에 어떤 개념이 맞는지"를 운영자 혼자 다 맞출 수 없다. 이 판단은 실제로 그 문장을 읽은 사용자가 가장 잘 안다.
사용자 요청(2026-10-18): 원문과 비유가 맞지 않으면 사용자가 **입력 없이 버튼 한 번**으로 알려 주고, 그 결과가 그래프에 반영되는 피드백 루프. "이 피드백이 생명이니 UI/UX를 잘 설계할 것."

## 설계 원칙
1. **한 번 클릭으로 끝난다.** 글자 입력은 어디에도 없다. 이유 고르기·다른 개념 고르기는 선택 사항이고, 안 눌러도 첫 클릭만으로 기록된다.
2. **누르면 바로 달라진다.** 👎를 누르면 그 자리에서 다른 비유를 다시 만든다. 기록만 하고 아무 변화가 없으면 사용자는 다시 누르지 않는다.
3. **반영된 걸 보여 준다.** 내 피드백 때문에 결과가 바뀌었으면 말풍선에 "내 피드백 반영" 칩을 단다. 루프가 닫혔다는 걸 사용자가 본다.
4. **방해하지 않는다.** 묻는 팝업이나 모달, "평가해 주세요" 같은 요청은 없다. 버튼은 평소에 흐리게 있다가 말풍선에 마우스를 올리면 또렷해진다.
5. **언제든 되돌릴 수 있다.** 누른 직후 5초 동안 "되돌리기"를 보여 주고, 설정 화면에서 전부 보고 지울 수 있다.
6. **피드백은 근거 규칙을 넘지 못한다.** 피드백이 할 수 있는 건 기존 노드의 순위 조정, 기존 태그에 예문 추가, 노드 제외뿐이다. 새 태그(규칙 9)나 새 사실(규칙 1·2)을 만들지 않고, 공통 그래프 파일은 사용자 피드백으로 직접 바뀌지 않는다(규칙 3).

## 말풍선 화면

비유가 나왔을 때 (맨 아래 줄에 버튼 두 개):
```
┌──────────────────────────────────────────┐
│ 쉬운 뜻   손실도 이익도 함께 커지는 투자 방식이에요 │
│ 메이플로 보면  높은 별에서 스타포스를 누르는 것과 같아요 │
│ [근거: 스타포스 강화] [보유 자산 손실 위험]          │
│ groq                         👍  👎   설정 │
└──────────────────────────────────────────┘
```

👎를 누르면 같은 자리에서 바뀐다 (입력 없음, 칩 하나만 눌러도 되고 안 눌러도 된다):
```
┌──────────────────────────────────────────┐
│ 이 문장엔 '스타포스 강화'를 안 쓸게요   되돌리기 │
│ 더 맞는 개념이 있나요?                        │
│ [메소 인플레이션] [경매장] [없어요]             │
│ 왜 안 맞았나요? (선택)                        │
│ [비유가 억지예요] [뜻이 틀렸어요] [사실이 틀렸어요] │
│ ⟳ 다른 비유 찾는 중…                         │
└──────────────────────────────────────────┘
```
- "더 맞는 개념" 칩은 검색 후보 중 나머지 2개다. 하나를 누르면 그 개념을 근거로 바로 다시 비유한다(LLM 1회, 근거 검증은 그대로).
- 아무것도 안 누르면 다음 순위 후보로 다시 비유한다. 칩은 3초 뒤 접힌다(말풍선에 마우스가 있으면 유지).
- "뜻이 틀렸어요"는 그래프 문제가 아니라 LLM 문제로 기록한다(T-122 품질 자료). "사실이 틀렸어요"는 공통 노드 제보로 간다(T-118, D-3).

비유를 못 찾았을 때 (지금은 "억지로 만들지 않았어요"로 끝난다):
```
│ 메이플에서 딱 맞는 비유를 찾지 못했어요.            │
│ 혹시 이 중에 있나요?  [스타포스 강화] [큐브] [경매장] │
```
- 후보 칩을 누르면 그 개념으로 비유를 만든다. 이게 가장 값진 피드백이다: 검색이 놓친 문장 ↔ 개념 쌍을 사용자가 직접 알려 준다(T-113의 금융 문장이 정확히 이 경우).

👍를 누르면: 버튼이 잠깐 채워지고 "고마워요"만 보인다. 다른 변화는 없다.

반영 표시:
```
│ [근거: 큐브] [무작위 재추첨] [내 피드백 반영]       │
```

세부:
- 버튼 크기 28px 이상, `aria-label`("잘 맞아요", "안 맞아요"), 키보드 포커스 가능. 메이플 테마에서는 잠재능력 등급색을 뜻대로: 👍 반영 표시 = 레전드리 초록(근거 칩과 같은 계열), 👎 = 중립 회색(빨강으로 "잘못"을 강조하지 않는다). 그 외 관심사는 중립 테마(규칙 6).
- 자동 모드에서 말풍선으로 마우스를 옮겨도 닫히지 않아야 버튼을 누를 수 있다(지금 동작 확인 필요, T-106).
- 문구는 존댓말 짧게(규칙 5). 밈 말투는 "고마워요" 정도로만 아낀다(규칙 11, `docs/naming-meme.md`).

## 피드백이 반영되는 세 단계

| 단계 | 언제 | 무엇이 바뀌나 | 어디에 |
| --- | --- | --- | --- |
| 1. 그 문장 | 누른 즉시 | (문장, 노드) 쌍 제외 또는 고른 노드로 고정. 결과 캐시 무효화 | 기기 안 피드백 층 |
| 2. 비슷한 문장 | 다음 호버부터 | 피드백한 문장 벡터를 기억해 두고, 새 문장과 코사인이 높으면(기본 0.92 이상) 그 노드에 감점·가점(상한 ±0.1). 👎가 같은 노드에 여러 문장 쌓이면 오버레이 `nodeBoosts`(하한 -0.2) | 기기 안 피드백 층, 로그인 시 오버레이 |
| 3. 그래프 자체 | 운영자 승인 뒤 | "더 맞는 개념" 교정 문장 → 그 노드의 최고 태그에 **예문 후보**(T-113에서 효과가 가장 컸던 수단). 👎 3건 → T-118 제외. 👍·교정 쌍 → 평가셋·회귀 가드 후보 | 내 그래프는 내 오버레이에 바로, 공통 그래프는 승인 큐 → `eval --guard` 회귀 0 확인 → 새 판본 |

- 2단계의 "문장 벡터 기억"은 문장 원문 없이 벡터와 해시만 둔다. 원문은 1단계 목록(설정 화면 표시용)에만, 기기 안에만 둔다.
- 3단계에서 예문을 추가할 때도 T-113의 원칙을 따른다: 승인 전 `npm run eval -- --guard`로 잘 맞던 문장이 새로 틀리지 않는지 확인한다. 피드백으로 들어온 👍 쌍은 회귀 가드 목록을 계속 키운다.
- 피드백으로 만든 예문도 멸칭·실존 인물 필터(T-114)를 지나야 한다.

## 결과
- 사용자 한 명의 피드백은 그 사용자에게 바로 보인다. 공통 그래프는 여러 사람의 신호가 모이고 운영자가 승인한 뒤에만 바뀐다(D-3 흐름 유지).
- 로그아웃 상태에서도 1·2단계가 돌아가도록 피드백은 사용자 크롬 프로필(`chrome.storage.local`)에 저장한다. 규칙 3("로그아웃 = 공통만")의 예외로 D-7에서 정했다(2026-10-18). 로그인·서버가 생기면 오버레이로 옮긴다.
- 웹페이지 문장(메일·은행 등)이 공통 개선용으로 서버에 가면 개인정보 문제다. 서버 전송 동의는 설치 직후 첫 실행 화면(T-116)에서 한 번만 받는다: 미리 선택 없이 [보내기] / [내 기기에만], 넘기면 기기에만. 말풍선 안에서는 묻지 않는다. 보낼 때는 숫자·메일 주소·이름 같은 부분을 가린다(D-7 결정 2026-10-18, T-107과 함께).
- 피드백 비율(호버 대비 👍/👎/교정)이 검색 품질의 실사용 지표가 된다. EVAL_LOG의 오프라인 평가와 함께 본다.

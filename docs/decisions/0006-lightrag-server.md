# 0006 검색을 LightRAG 서버(EC2)로 옮기고, 추출은 로컬 맥에 맡긴다

- 상태: 제안 (2026-09-29). L0 관문(서버 hit@1 ≥ 브라우저 hit@1)을 통과하면 채택으로 바꾼다.
- 설계: [architecture-lightrag.md](../architecture-lightrag.md)
- 영향: 0002(브라우저 안 임베딩)는 오프라인 대체 경로로 격하, 0005(제공자 레지스트리)는 서버로 이동, 0001·0003·0004는 유지

## 배경
손으로 쓴 공통 그래프(노드 18개)로는 비유 대상이 금방 바닥난다. 가이드 문서에서 그래프를 자라게 해야 하는데, 문서 추출은 LLM 호출이 많아 클라우드로 돌리면 비용과 무료 티어 한도가 문제다. 사용자에게는 16GB M2 맥이 있다.

## 결정
- 그래프 RAG 엔진은 LightRAG. 커뮤니티 요약이 없어 증분 추가가 싸고, 관계의 high-level 키워드가 우리의 추상 태그 역할을 한다.
- EC2(`t4g.medium`)에 LightRAG를 라이브러리로 감싼 `analogy-api`(FastAPI)를 둔다. LightRAG 서버의 요청별 워크스페이스 라우팅이 아직 없어서(#3631) 워크스페이스별 인스턴스를 직접 관리한다.
- 추출·설명 병합 요약 LLM = 맥의 Ollama(`gemma4:12b`), Tailscale(`tag:rag-server` → `tag:llm-node:11434`)로만 연결. 맥은 시간창에만 켜고, EC2 큐가 기다린다.
- 호버 경로(키워드·비유)는 클라우드 LLM(Gemini). 맥을 호버 경로에 두지 않는다.
- 추상 태그는 통제 어휘로 고정해 추출 프롬프트와 질의 키워드 프롬프트가 같은 목록을 쓴다. 원본은 `maplestory.json`의 `tags`.
- 임베딩은 EC2의 `bge-m3` 하나로 인덱싱·질의를 모두 처리한다.
- 근거 검증(`nodeId`가 후보에 없으면 비유 숨김)은 서버에서 그대로 한다.

## 결과
- 호버당 LLM 호출이 1회에서 2회로 는다(키워드 + 비유). 지연 2~3초 예상, 캐시로 줄인다.
- 서버가 키를 보관하므로 T-204(키 프록시)가 자연히 해결된다.
- 16GB 맥의 12B 모델은 LightRAG 권장(32B+)에 못 미친다. 시드 그래프와 통제 어휘로 뼈대를 고정하고, L1의 A/B 실험으로 품질을 확인한다.
- 월 비용 약 $31(PoC), 로그인 공개 후 약 $55.

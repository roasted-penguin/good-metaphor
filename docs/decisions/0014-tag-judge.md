# 0014 판정기(객관식 LLM)로 추상 태그 고르기: 호버에는 넣지 않고 평가 도구로 둔다

- 상태: 결정 (2026-11-22, T-120). 호버 경로 채택 안 함, `npm run eval -- --judge <id>` 오프라인 도구로 유지
- 갱신 (2026-11-22, T-184): 정밀 모드 추상화 호출에 판정을 합침. **정밀 모드에만 기본 켬**(`admin.json` `preciseTagJudge.enabled: true`). 지금 정밀 모드 대비 회귀 0·개선 10. 임베딩만 대비 회귀 1(홀드아웃 "명절 사과")은 판정 없는 정밀 모드에도 있는 회귀라 T-186으로 따로 고친다. 아래 "T-184" 절

## 배경
T-113 이후 남은 오답 대부분은 임베딩이 "단어가 비슷한 쪽"을 고르는 데서 온다(금융 주제 → 메소 노드 쏠림). 태그 유사도(코사인)는 평가셋에서 태그 top-1 26/44(59%)에 그친다. T-120은 글을 쓰지 않고 정해진 선택지에 확률로만 답하는 "판정기"에 "이 문장의 추상 구조는 태그 중 무엇인가"를 직접 묻는 실험이다. 원래 대상은 Jev(TypeSafe AI, 얼리 액세스)인데 키가 아직 없어, 같은 인터페이스로 Gemini 객관식(`gemini-choice`)을 먼저 쟀다.

## 구현
- `extension/lib/judges.js`: 판정기 레지스트리 `JUDGES`(규칙 7과 같은 방식) + `judge(판정기, { text, question, choices, multi }) → [{ id, p }]`.
  - `gemini-choice`: `providers.js` `complete`(json)를 그대로 써서 HTTP·503 재시도·thinking 대체를 중복하지 않는다. 응답 `{"answers":[{id,p}]}`를 `parseChoiceJSON`이 읽고, `normalizeChoices`가 목록 밖 id를 버리고(규칙 9) 다중 선택은 [0,1]로 자르고 단일 선택은 합 1로 나눈다.
  - `jev`: 항목만 있다. 공개 API 문서를 찾지 못해 키가 없으면 "키가 필요해요", 있으면 "아직 미지원"을 던진다. 키·문서가 생기면 `KINDS.jev`만 채운다.
  - 모두 클라우드(규칙 8).
- 질문 1: `TAG_QUESTION` + `tagChoices(tags.json)`. 선택지는 태그 파일에서 만들어 개수를 가정하지 않는다(지금 21개).
- `retrieve`의 선택 옵션 `tagJudge: { p, mode, weight }`(`combineTagSim`). 없으면 결과가 이전과 같다(단위 테스트).
  - `replace`(대신): 태그 점수 = 판정 확률 p. 감점은 임베딩 쏠림 보정이라 빼고 쓴다.
  - `combine`(함께): 태그 점수 = 유사도 − 감점 + w·p. w는 결과를 보기 전에 0.05로 정했다(태그 유사도 1·2위 차가 보통 0.01~0.05).
- `tools/eval.mjs --judge <id>`(`tools/eval-judge.mjs`): 판정 결과를 `.tmp/judge-<id>-<모델>.json`에 캐시(다시 돌리면 호출 0), `--rpm`(기본 10)으로 간격, 503·429는 10·20·40·80초로 물러서며 다시. 판정 태그 top-1, 대신·함께 hit@1/@3, 혼합 대비 1위 회귀·개선, 음성 문장, 가드 놓침, 판정 지연(처음 호출 때 잰 값)을 찍는다.

## 결정
- **호버 경로에는 넣지 않는다.** 채택 조건은 (1) 임베딩만 대비 1위 회귀 0(가드·평가셋·홀드아웃), (2) 받아들일 만한 지연이었다. 두 조건 모두 못 넘는다.
  - 회귀: 가장 좋은 `combine`도 홀드아웃 1, 음성 1, 식당 1(식당 가드 포함)이다. "회귀 0" 원칙(사용자, 2026-10-18)상 합계가 크게 올라도 채택하지 않는다.
  - 지연: 중앙값 +1초, p90 +3초, 최대 +10초. 지금 호버가 3.6~9.1초라 뜻이 먼저 나오기까지(T-117)를 더 늦춘다. 503·429가 오면 생성 체인과 한도를 다툰다.
  - 그래서 `admin.json` 설정도 만들지 않았다(꺼진 설정을 둘 이유가 없음).
- **평가 도구로는 남긴다.** 태그 top-1이 크게 오른다(평가셋 59% → 86%, 홀드아웃 63% → 94%). 판정이 "정답 태그"의 좋은 근사라서, 사람이 노드 태그·태그 예문을 고칠 때 오프라인으로 쓴다. 캐시 덕분에 다시 돌려도 비용이 없다.
- Jev는 키·API 문서를 받으면 같은 표로 다시 잰다. 회사 주장(0.07~0.5초)이 맞으면 지연 조건은 넘을 수 있지만, 회귀 조건은 같은 잣대다.

## 결과·후속 (TASKS에 새 번호로 올릴 후보)
- 정밀 모드(이미 LLM 2회)의 추상화 호출에 태그 질문을 함께 묻는 방안: 호출이 늘지 않아 지연 조건을 피한다. 회귀 조건은 같은 표로 다시 잰다.
- 판정이 맞는데 순위가 틀린 문장(명절 사과 → `meso_inflation`)은 노드 태그를 다시 볼 신호다. 판정 결과를 태그 검수 보조로 쓴다(사람 승인 유지).
- 음성(구조 없는 일상 문장)에 판정이 태그를 주는 문제: 판정 확률 하한(예: p ≥ 0.8만 가산)이나 "해당 없음" 선택지를 두고 다시 잴 수 있다. 이번에는 결과를 보고 고르면 과적합이라 재지 않았다.
- 서버(LightRAG, ADR 0006)의 질의 키워드 단계는 이미 LLM을 부르므로, 같은 판정을 거기에 얹는 쪽이 지연 부담이 없다.

## T-184: 정밀 모드 추상화 호출에 판정 합침 (2026-11-22)

### 구현
- 정밀 모드는 원래 검색 전에 추상화 LLM을 한 번 부른다. 같은 호출이 JSON `{"abstract": "...", "tags": [{id, p}]}`로 추상 구조와 태그 확률을 함께 돌려준다. **호출 수는 그대로**(합친 호출 지연 중앙 1.2~1.3초, 한도 리셋 직후 식당 홀드아웃 8문장만 3.0초. 예전 추상화 호출과 같은 자리라 직렬 호출이 늘지 않음).
  - 프롬프트 `prompt.js` `buildAbstractJudgePrompt`: 추상화 규칙(T-122 전문용어 풀어 쓰기 포함)은 글 응답 프롬프트와 같은 줄을 쓰고, 선택지는 `tagChoices(graph.tags)`로 tags.json에서 만든다(규칙 9, 개수 가정 없음). 맨 뒤에 예약 선택지 `none`("해당 구조 없음")을 붙인다.
  - 파싱 `judges.js` `parseAbstractJudge`: JSON이 아니면 응답 전체를 추상 구조로 보고 판정 없음(null). 목록 밖 id는 버린다(`normalizeChoices`).
  - `judgeTagProbs(answers, { floor })`: `none`이 가장 높은 태그 이상이면 `[]`, 하한 아래 태그는 버린다. `isStructureless`: 판정은 있었는데 쓸 태그가 없음.
  - `pipeline.js` `runAbstract({ tagJudge: { tags, floor } })`: **구조 없음이면 질의를 원문 그대로** 쓴다(추상 구조는 debug에만). 아니면 예전처럼 추상 구조 + 원문. 판정 확률은 `retrieve` `tagJudge: { p, mode: 'combine', weight }`(T-120 결합, w=0.05)로.
  - `background.js`: `admin.preciseTagJudge.enabled`일 때만 `tagJudge`를 넘긴다. 꺼져 있으면 예전 글 응답 프롬프트 그대로(동작 변화 0). `debug.tagJudge = { probs, none, structureless }`. 일반 모드는 손대지 않았다.
  - 규칙 1(후보 밖 nodeId 숨김)·근거 검사는 그대로(`runAnalogy` 변경 없음, 단위 테스트로 확인).
- 평가 `npm run eval -- --judge precise`(`tools/eval-judge.mjs` `loadPreciseJudgeResults`): 확장과 같은 프롬프트·파서로 Gemini를 불러 `.tmp/judge-precise-<모델>.json`에 캐시(없음 포함 전체 확률이라 하한을 바꿔도 다시 안 부름). 임베딩만 / 정밀(판정 없음, 합친 응답의 추상 구조) / 정밀+판정 / 원문+판정 네 줄과 문장별 1위 변화(`rank1Changes`)를 찍는다. `--judge-floor`, `--judge-sweep`(하한 후보 한 줄씩), `--judge-offline`(한도 소진 때 캐시만).

### T-120 회귀 세 문장
1. **"명절 직전 사과 한 상자 값"(홀드아웃)**: `meso_inflation`의 태그 `market_price`는 사실("메소가 많이 풀리면 아이템 가격이 오르고 메소 가치가 떨어진다")과 정직하게 맞지 않는다(그건 `inflation`). 빼 보았지만 **임베딩만 모드에서 검증셋 가드 회귀 1**("정부가 국채를 대량으로 찍어 돈을 풀자 장바구니 물가가 뛰었다" `meso_inflation` → `auction`)과 홀드아웃 hit@3 27→26이 생겨 **기각**(그래프 그대로). 이 문장은 판정(market_price 0.95)이 맞는데도 정밀+판정·원문+판정·**판정 없는 정밀 모드** 모두에서 `meso_inflation`이 1위다. 원인은 `meso_inflation`의 두 번째 태그가 판정 가산을 받는 것(원문+판정)과 추상 구조 질의 자체(정밀).
2. **구조 없는 일상 문장("타이어가 펑 하고 터졌다")**: `none` 선택지로 판정이 `none` 1.0을 준다(T-120 판정기는 `loss_risk` 0.7). 그런데 회귀 원인은 판정이 아니라 **정밀 모드 추상 구조 질의 자체**였다("이동 중이던 탈것의 부품에 갑작스러운 고장" + 원문 → `starforce`, 판정 없는 정밀 모드에서도 음성 5/6). 그래서 구조 없음이면 원문으로 찾게 했다. 음성 6/6.
3. **식당 가드 "유튜브 채널을 넘길 때…"**: 판정이 불확실했다(`scarcity_value` 0.6, `none` 0.3). 같은 방식으로, 하한을 넘는 태그가 없으면 구조 없음 → 원문 질의. "항공 마일리지…"(판정 `daily_accumulation` 0.5)도 같다. 둘 다 판정 없는 정밀 모드에서 생기던 식당 가드 놓침이다.

### 하한 고르기 (홀드아웃은 보지 않음)
후보 0·0.5·0.6·0.7·0.8·0.9를 메이플 평가셋·검증셋·가드와 식당 평가셋·식당 가드로만 쟀다(`--judge-sweep`, 홀드아웃 실행 전). 조건: 가드 놓침 0(메이플·식당), 검증셋 회귀 0, 음성 6/6. 메이플은 모든 후보가 같았고(44/44·14/14·가드 0·음성 6/6), 식당은 0→15/21·가드 놓침 2, 0.5→14·2, 0.6→15·1, **0.7·0.8·0.9→16/21·0**. 조건을 넘는 가장 낮은 값 **0.7**을 골랐다(추상 구조를 쓰는 문장을 가장 많이 남김). 그 뒤에 홀드아웃을 0.7로 한 번만 쟀다.

### 결정
- 채택 조건(사용자 지시): 1위 회귀 0, 단 순이익이 크면 바꾸고 틀려진 문장은 새 작업으로. 구현 에이전트는 임베딩만 대비 회귀 1(홀드아웃 "명절 사과") 때문에 꺼진 채로 넘겼다.
- **판정(메인 세션, 2026-11-22): 정밀 모드에 기본 켬**(`preciseTagJudge.enabled: true`, 하한 0.7·w 0.05·combine). 이유: (1) 켜고 끄는 비교 대상은 지금 정밀 모드다. 그 대비 **회귀 0, 개선 10**(평가셋 1·음성 1·홀드아웃 4·식당 2·식당 홀드아웃 2), 식당 가드 놓침 2→0. (2) 남은 1문장은 판정 없는 정밀 모드에서도 틀린다. 꺼도 고쳐지지 않는다. ## T-187: `meso_inflation` 노드 글 고쳐 쓰기 (2026-11-22)
- **바꾼 것:** `meso_inflation` 첫 사실을 "게임 안에 메소를 많이 풀면 메소의 가치가 떨어지고 물가가 뛴다."로(예전 "…아이템 가격이 오르고 메소의 가치가 떨어진다."). 개별 아이템 값 대신 화폐 가치·전반 물가로 쓴 것이고 새 사실은 없다. 출처 공지(134898, "메소 인플레이션 억제", 메소 획득량이 늘면 메소 인플레이션이 심해짐)를 다시 열어 확인했다. 태그(`inflation`, `market_price`)와 `meso` 노드는 그대로다.
- **결과(실제 확장):** 모든 셋·모든 모드(임베딩만·정밀·정밀+판정)에서 1위 회귀 0. 홀드아웃 개선 2: "귤 풍년"(임베딩만), "명절 사과"(정밀·정밀+판정, T-184부터 남은 회귀). "이사철 견적"(정밀)과 "Gas prices"는 그대로 틀린다.
- **왜 태그는 못 뺐나:** `market_price`를 빼면 국채 문장에서 `meso_inflation`의 태그 점수가 `inflation`(감점 0.03)으로 떨어진다. 그 차이는 노드 글의 직접 유사도로 메워지지 않았다(사실 문장을 바꿔도 국채 여유 −0.005~−0.006). `auction`과 `meso_inflation`이 같은 `market_price` 태그를 가지는 한, 시장 수급 문장과 통화량 문장의 순위는 두 노드 글의 직접 유사도 차(0.001~0.002 수준)로 갈린다. 남은 문장까지 고치려면 `auction` 노드 글이나 태그 예문·감점 쪽을 봐야 한다.
- **대가:** 국채 가드 여유가 +0.0052 → +0.0034로 줄어 여유 < 0.005 가드가 하나 늘었다(아파트 호가 가드는 +0.0003 → +0.0014로 늘었다). `--margin-guard`는 dev에서도 실패 중이라 T-188이 함께 본다.

# 0007 최신화: 패치 노트는 원문으로, 밈은 승인한 용어 카드로

- 상태: 제안 (2026-10-11). L2에서 T-423·T-424로 구현한다.
- 설계: [architecture-lightrag.md](../architecture-lightrag.md) "최신화"
- 영향: CLAUDE.md 규칙 2(수치 금지)의 범위를 손으로 쓰는 사실로 좁힌다. 0006(LightRAG 서버)의 인덱싱 흐름에 두 입력을 더한다.

## 배경
메이플은 매주 패치되고 커뮤니티 밈도 계속 바뀐다. 2026-10 검수에서 손으로 쓴 사실 18개 중 3개가 패치로 틀려져 있었다(스타포스 흔적 복구, 샤이닝 스타포스 타임, 큐브 판매 중단). 사용자는 최신 패치와 밈을 기준으로 비유가 나오길 원한다.

막는 조건이 둘 있다.
- D-5: 나무위키·인벤 원문은 수집·저장하지 않는다(저작권, 약관, 데이터베이스권).
- 규칙 11: 새 밈 상당수가 멸칭이거나 실존 인물이라, 자동으로 넣으면 말풍선에 그대로 나올 수 있다.

## 결정
- **두 갈래로 최신화한다.**
  - 게임 정보: 공식 패치 노트·가이드를 **원문 그대로** 인덱싱한다. 정기 점검 다음에 새 글을 감지해 넣고, 같은 문서의 이전 판은 `adelete_by_doc_id`로 지운다. `doc_id = 출처 URL + 판본`, 문서마다 `published_at`을 남긴다.
  - 커뮤니티 밈·은어: 주 1회 나무위키·인벤을 **읽기만** 하고, LLM이 **용어 카드** 초안을 쓴다. 카드는 사람이 승인한 것만 넣는다. 원문은 저장하지 않는다.
- **용어 카드 형식** (T-114와 같은 형식): `term`, `variants`(띄어쓰기·우회 표기), `meaning`(우리 문장), `category`(A 은어 / B 밈 / C 실존 인물 / D 멸칭), `links`(대응 게임 시스템 id), `first_seen`, `sources`(URL만), `status`(제안 / 승인 / 폐기).
- **분류별 행선지**
  - A 은어 → 연결된 게임 시스템 엔티티의 별칭. 질의 키워드 확장에도 쓴다.
  - B 밈 → 말투 사전. 비유 본문의 근거로는 쓰지 않는다.
  - C 실존 인물, D 멸칭 → 그래프에 넣지 않고 금칙어 목록으로 간다.
- **최신 우선**: 같은 게임 시스템에 대한 근거가 여러 판이면 `published_at`이 최신인 것을 후보 앞에 둔다. 말풍선 근거에 기준 날짜와 출처 링크를 보인다.
- **규칙 2 범위 조정**: 손으로 쓰는 공통 그래프 사실과 용어 카드에는 지금처럼 수치를 넣지 않는다. 공식 패치 노트 원문은 날짜와 함께 수치까지 넣는다. 판이 바뀌면 통째로 교체되므로 틀린 수치가 남지 않는다.
- **금칙어 검사는 출력 직전에 한다.** 프롬프트 규칙만 믿지 않는다. 걸리면 해당 필드를 비우고 `rejected`에 이유를 남긴다(규칙 1의 `nodeId` 검증과 같은 방식).

## 결과
- 패치 다음 날부터 새 시스템을 근거로 비유가 나온다. 단, 맥 추출 시간창을 거치므로 반영까지 최대 하루 정도 걸린다.
- 밈은 사람이 승인해야 들어가서 느리지만, 멸칭이나 실존 인물이 새어 나갈 위험을 막는다.
- 패치 노트는 공지 형식이 바뀌면 감지 스크립트가 깨질 수 있다. 실패하면 알림만 하고 이전 판을 유지한다.
- 용어 카드 승인 화면은 T-422 검수 화면(테일넷 전용)을 함께 쓴다.

`docs/TASKS.md`와 `CLAUDE.md`의 "지켜야 할 규칙"을 읽고 아래 순서로 진행해.

1. **고르기**
   - 인자가 있으면 그 작업: $ARGUMENTS
   - 없으면 "한눈에 보기" 표에서 상태가 `대기`이고, "먼저 끝나야 할 것"이 모두 `완료`인 작업 중 우선순위(P0 → P1 → P2), 표 순서로 첫 번째.
   - 고른 작업이 `결정 필요` 항목(D-x)에 막혀 있으면 멈추고, 그 결정의 선택지와 추천을 요약해서 나에게 물어봐.
2. **계획** 작업의 "완료 기준"을 인용하고, 고칠 파일과 추가할 테스트를 5줄 이내로 적어. 설계를 바꾸는 작업이면 ADR이 필요한지도 적어. 그다음 바로 진행해(질문은 정말 막혔을 때만).
3. **구현** 테스트를 먼저 쓸 수 있으면 먼저 쓴다. 순수 로직은 `tests/unit`, 확장 동작은 `tests/e2e`. `src/offscreen-src.js`를 고쳤으면 `npm run build`.
4. **확인** `npm test` 통과. 검색·생성에 영향이 있으면 `npm run eval`(모델을 못 받는 환경이면 `npm run eval:fallback`이라고 명시)하고 `docs/EVAL_LOG.md`에 한 줄 추가.
5. **기록** `docs/TASKS.md` 표의 상태를 `완료`로 바꾸고 작업 로그에 날짜·ID·한 줄 요약. 새로 발견한 문제는 새 T-번호로 표에 추가.
6. **커밋** `feat(T-xxx): 요약` 또는 `fix(T-xxx): 요약`.

마지막에 무엇을 했는지, 무엇을 확인하지 못했는지(예: 실제 키 없이 테스트함)를 3줄 이내로 알려 줘.
